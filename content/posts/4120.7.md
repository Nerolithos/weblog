# CSC4120 W10  Dynamic Programming

# I. Fibonacci & Shortest Path DP

## DP Basics

DP 的两个基本思想：

1. **Recursion**：把问题拆成子问题，并通过子问题的解得到原问题的解。
2. **Tabulation** / Memoization：每个子问题只计算一次，把结果存起来供以后使用；需要子问题解时查表，若无记录立即计算。

</br>

### Fibonacci Memorization

F<sub>1</sub> = F<sub>2</sub> = 1，F<sub>n</sub> = F<sub>n-1</sub> + F<sub>n-2</sub>

```python
def fib(n):
    if n <= 2:
        return 1
    return fib(n - 1) + fib(n - 2)
```

计算斐波那契 T(n) = T(n-1) + T(n-2) + O(1) = 𝛩(2<sup>n</sup>)

#### Memorized DP

避免指数级时间：计算出 F<sub>k</sub> 后保存结果——

```python
memo = {}
def fib(n):
    if n in memo: return memo[n]
    if n <= 2: result = 1
    else: result = fib(n - 1) + fib(n - 2)
    memo[n] = result
    return result
```

因为只有 F<sub>1</sub>, F<sub>2</sub>, ... F<sub>n</sub> 这 n 个不同的子问题，每个子问题第一次访问时真正计算；**虽然计算仍然无序，但之后访问时直接查表**，花费 O(1)。因此 **T(n) = 𝛩(n)**，额外**空间开销 S(n) = 𝛩(n)** (Memorization table + Recursion stack)

⚠️ 核心：子问题算且只算一次

</br>

### Bottom-up (non-recursive) DP 

我们也可以完全不使用递归，而是按顺序计算：F<sub>1</sub> → F<sub>2</sub> → ... → F<sub>n</sub>

```python
def fib(n):
    dp = [0] * (n + 1)  # 初始化长n+1的全0数组
    dp[1] = dp[2] = 1
    for k in range(3, n + 1):
        dp[k] = dp[k - 1] + dp[k - 2]
    return dp[n]
# 甚至只存每项的两个前序——
def fib(n):
    if n <= 2: return 1
    a, b = 1, 1
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b
```

**T(n) = 𝛩(n)，S(n) = 𝛩(n) (⚠️ 只存两项时 𝛩(1))**，实际运行因为没有递归更快，但计算次数和 Memorized DP 相同。

Bottom-up 的计算顺序必须遵守 Dependency Ordering，即子问题 **Dependency Graph** 需要拓扑排序——⚠️ 必须是 DAG (**No circular dependency** 无环)。算法先填充没有依赖的表项，然后循环按拓扑顺序处理 (其依赖已知) 的表项。

- dependency graph (依赖图) 的边全部 **reverse** 就是 **causality graph (因果图) == tropological order**

这对高维依赖也适用，比如 2D：(𝑖, 𝑗) depends on (𝑖−1, 𝑗) & (𝑖, 𝑗−1)：

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-14%2009.45.02.png)

⚠️ DP 适用的主要条件：

- 可以从子问题的解组合得到原问题的解。
- 子问题间不存在 **Circular Dependency**。
- 存在 Overlapping Subproblems (重叠子问题)。
- 不同子问题数量相对较少，最好是 Polynomial。

## Shortest Path DP

设某有向图从 s  到 v 的最短距离为 δ(v)，直接想到 [**Bellman Equation**](https://blog.nero-lithos.com/posts/4120.6/#optimal-substructure--bellman-equation): δ(v) = min\{δ(u) + w(u, v)} 很合理，问题是如果图中有环 (non-DAG, u→t→u) 就有循环依赖，无法直接 DP 计算。

> 如果状态间存在循环依赖，试引入一个额外约束 k，切分子问题，把循环依赖转化为不同轮之间的依赖。

定义 δ<sub>k</sub>(s, v) 表示 s⇝v **最多**使用 k 条边的最短距离，这样循环依赖就从 δ(t) ↔ δ(u) 变为 δ<sub>k</sub>(t) → δ<sub>k-1</sub>(u) & δ<sub>k</sub>(u) → δ<sub>k-1</sub>(t) ——所有依赖都指向上一层 k-1，不再成环。

我们希望求 δ<sub>k</sub>(s, v)，初始化 δ<sub>0</sub>(s, s)=0，最优路径有两种可能：

- 不使用第 k 条边，距离为 δ<sub>k-1</sub>(s, v) 
- 使用最后一条边 (u,v)，那么到 u 的路径最多使用 k-1 条边，距离为 δ<sub>k-1</sub>(s, u) + w(u, v)

我们枚举所有可能的前驱 \(u\)，选最小值。因此 **Bellman-Ford DP** 完整递推式为：

> **δ<sub>k</sub>(s, v) = min\{δ<sub>k-1</sub>(s, v), min<sub>(u, v)∈E</sub> \[δ<sub>k-1</sub>(s, u) + w(u, v)]}**
>
> 1、**保留上一轮旧值继续比较**；2、**只能使用上轮距离结果**，不能使用本轮刚更新的值。
>
> (**课件使用了 δ<sub>k</sub>(s, v) = min<sub>(u, v)∈E</sub> \[δ<sub>k-1</sub>(s, u) + w(u, v)] 实际是不严谨的**)

⚠️ **只需要计算到 k =|V|− 1**，因为 δ<sub>|V|−1</sub>(s, v) = δ(s, v) ——在不存在负权环的情况下，如果一个最短路径重复访问某个节点，就包含一个 Cycle。这个 Cycle 的总权重不能为负，否则与无负权环的假设矛盾。删除这个 Cycle 不会增加路径长度，所以总存在一条最短的 Simple Path，最多经过 |V|− 1 条边 (逻辑类似 [Bellman-Ford](https://blog.nero-lithos.com/posts/4120.6/#bellman-ford-algorithm))

时间复杂度：对每个状态枚举所有前驱，子问题个数 x time/sub-problem = (|V|x|V|)x|V|

实际上，对于固定的 k，把所有节点的前驱边加起来，每条边只需要检查一次，因此每轮实际：O(|V|+|E|)，总共 O(|V|(|V|+|E|)) = **O(|V||E|)** (连通图)

</br>

### Example

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-14%2010.27.52.png)

Initialize δ<sub>0</sub>(s) = 0, δ<sub>0</sub>(t) = δ<sub>0</sub>(u) = δ<sub>0</sub>(v) = ∞;

Round 1: δ<sub>1</sub>(u) = min(δ<sub>0</sub>(u); 0+1, ∞+4) = 1, δ<sub>1</sub>(v) = min(δ<sub>0</sub>(v); 0+3, ∞+1) = 3, δ<sub>1</sub>(t) = (δ<sub>0</sub>(t); ∞+3, ∞+1) = ∞

Round 2: δ<sub>2</sub>(u) = min(1; 0+1, 3+4) = 1, δ<sub>2</sub>(v) = min(3; 0+3, 1+1) = 2, δ<sub>2</sub>(t) = min(∞; 1+3, 3+1) = 4

Round 3: δ<sub>3</sub>(u) = (1; 0+1, 2+4) = 1, δ<sub>3</sub>(v) = (2; 0+3, 1+1) = 2, **δ<sub>3</sub>(t) = min(4; 1+3, 2+1) = 3**

</br>

### 如何设计 DP Recurrence

⚠️ **Guess the last decision** (猜测最后一步)：以最短路径为例，我们不知道最后一条边是哪条，所以枚举所有可能的 u；**然后对每个候选 δ<sub>k-1</sub>(s, u) + w(u, v) 取 min** 

关键：(Polynomial) \# sub-problem = a; (polynomial) \# possible guess/sub-problem = b; Complexity = axb

**反之不成立**！Longest Simple Path 不可拆作“DP\[s, t]=max\{DP\[s, v] + DP\[v, t]}”，因为两段分别是各自子问题的最优解路径可能重复使用某些节点 (Not independent)：路径不一定简单

> Optimal Substructure 不仅要求子问题有最优解，还要求这些**子问题的解能够合法地组合**：**sub-problems can be solved independently**

## All-Pairs Shortest Paths

我们以往讨论的是 Single-Source Shortest Paths (SSSP)：给定源点 s 求距

All-Pairs Shortest Paths (APSP) 求所有两个节点之间的最短距离 δ(i, j)，假设无负权环，输出是一个 nxn 矩阵

### 方法一：限制边数

类似的，定义 d<sub>ij</sub><sup>(m)</sup> 表示 i⇝j 使用最多 m 条边的最短距离，初始化 d<sub>i=j</sub> = 0, d<sub>i≠j</sub> = ∞

递推 d<sub>ij</sub><sup>(m)</sup> = min\{d<sub>ik</sub><sup>(m-1)</sup> + a<sub>kj</sub>} 其中 a<sub>kj</sub> 表示从 k 到 j 的直接边权，没有边时为 ∞，且 a<sub>jj</sub> = 0

- 猜测最后一条边是 k → j，**O(|V|<sup>2</sup>|E|)** ～ O(n<sup>4</sup>)

</br>

### 方法二：限制 Intermediate Vertices

它不限制边数，而是限制路径中允许使用哪些中间节点。称为 **Floyd-Warshall** 算法 (O(|V|<sup>3</sup>))

定义 d<sub>ij</sub><sup>(m)</sup> 表示 i⇝j 只能使用编号在 \{1, ... m} 中的节点的最短距离

- 情况 A：不经过节点 m：d<sub>ij</sub><sup>(m)</sup> = d<sub>ij</sub><sup>(m-1)</sup>
- 情况 B：经过节点 m：d<sub>ij</sub><sup>(m)</sup> = d<sub>im</sub><sup>(m-1)</sup> + d<sub>mj</sub><sup>(m-1)</sup>

> Floyd-Warshall：**d<sub>ij</sub><sup>(m)</sup> = min\{d<sub>ij</sub><sup>(m-1)</sup>, d<sub>im</sub><sup>(m-1)</sup> + d<sub>mj</sub><sup>(m-1)</sup>}**

```python
def floyd_warshall(dist):
    n = len(dist)
    for m in range(n):
        for i in range(n):
            for j in range(n):
                dist[i][j] = min(
                    dist[i][j],
                    dist[i][m] + dist[m][j]
                )
    return dist
```

**不能随意交换三层循环顺序**。如果把 `m` 放到最内层，通常就不再遵循这个 DP 的依赖顺序。

# II. DP Examples

2 个非常相似的 DP 问题讲解：

- Rod Cutting (钢条切割)：怎样切割才能获得最大收益？
- Text Justification (文本排版)：怎样换行才能让排版最整齐？

> 猜测第一步怎么做，剩余部分交给 DP 求最优解。

</br>

## Rod Cutting

假设一根钢条长度为 n，不同长度的钢条有不同售价：

长度 i，价格 p\[i]：p\[1] = 1、p\[2] = 5、p\[3] = 8、p\[4] = 9

如果钢条长度为 4，不切时收益为 9；

- 切成 1+3：收益 1+8=9；
- 切成 2+2：收益 5+5=10，因此最优收益为 10。

### DP 定义与递推式

DP\[j] = 长度为 j 的钢条能获得的最大收益，我们猜测第一段切下来的长度是 i；

所以 DP\[j] = max<sub>1 ≤ i ≤ j</sub>\{p\[i] + DP\[j - i]}，初始条件 DP\[0] = 0，其中 i = j 代表不切割，直接出售整根钢条。

复杂度： 一共有 n 个 DP 状态，每个状态最多尝试 n 种切法：**T(n) = 𝛩(n<sup>2</sup>), S(n) = 𝛩(n)**；

计算顺序：`DP[0] → DP[1] → ... → DP[n]`。

## Text Justification

自动文本换行问题：假设一行最多容纳 10 个字符，我们希望安排单词，使每一行末尾剩余的空白尽量均匀。

定义了排版的不美观程度：Badness = Σ<sub>lines</sub>(extra spaces)<sup>2</sup>

平方用于惩罚并避免某一行特别短/特别长：

- 方案 A：0、8 个空格，成本 0<sup>2</sup> + 8<sup>2</sup> = 64；
- 方案 B：4、4 个空格，成本 4<sup>2</sup> + 4<sup>2</sup> = 32。

### DP 定义与递推式

定义 DP\[i] = 从第 i 个单词到最后一个单词的最小排版成本 (使用 0-based indexing)

假设我们决定把第 i 到第 j - 1 个单词放在第一行，剩余从 j 开始，那么：

总成本 = line\_cost(i, j - 1) + DP\[j]

尝试所有合法的 j，取最小值：DP\[i] = min<sub>i < j ≤ n</sub>\{line\_cost(i, j - 1) + DP\[j]}

初始条件 DP\[n] = 0

其中

<div class="math-display">
$$
\text{line\_cost}= \begin{cases} \infty,&\text{单词放不进一行}\\ (\text{行宽}-\text{所需字符数})^2,&\text{否则} \end{cases}
$$
</div>

计算顺序： 因为 `DP[i]` 依赖后面的 `DP[j]`，所以从右往左计算：`DP[n] → DP[n-1] → ... → DP[0]`；

复杂度： 一般为 **O(n<sup>2</sup>) 时间、O(n) DP 空间** (假设可以常数时间计算一行的成本，如果每行能容纳的单词数量有固定上限，实际可进一步降到 O(n))。

> 2 个问题的共同点：把一个序列分成若干段，使各段的总收益最大或总成本最小。

# III. More DP Examples

## Matrix Chain Parenthesization

矩阵乘法结果满足结合律 (AB)C = A(BC)，但不同计算顺序可能需要完全不同的计算成本——因为两个矩阵 A<sub>nxm</sub> B<sub>mxl</sub> 相乘的标量乘法次数为：nml。

**DP** Matrix Multiplication：**猜最后一次乘法**。不管括号如何放置，最后一步一定是把两个已经计算好的矩阵相乘，于是一定存在某个分割点 k，将整个问题分成左右子问题 (两个最后一步相乘的矩阵)。

定义 DP\[i, j] = 计算 A<sub>i</sub> · ... · A<sub>j</sub> 的最小成本，令 A<sub>t</sub> 的维度为 p<sub>t-1</sub>x p<sub>t</sub>，则 DP\[i, j] = min<sub>i<k≤j</sub>\{DP\[i, k] + DP\[k+1, j] + p<sub>i-1</sub>x p<sub>k</sub> x p<sub>j</sub>}

(边界条件 DP\[i, i] = 0 因为单个矩阵就没有乘法)

计算顺序是 **increasing substring size** (区间长度递增)：

- 长度 1：`DP[1,1]`, `DP[2,2]`……
- 长度 2：`DP[1,2]`, `DP[2,3]`……
- 长度 3：`DP[1,3]`, `DP[2,4]`……
- 直到长度 n。

因为长区间依赖短区间作为其分割结果，这就是**区间 DP 的 Topological Order**。

时间复杂度：共有 O(n<sup>2</sup>) 个区间，每个区间最多枚举 O(n) 个分割点——O(n<sup>3</sup>)

## Longest Common Subsequence

典型的二维 DP：找两个字符串最长公共子序列 Subsequence (可以不连续，但必须保持相对顺序的字符序列)

**DP** LCS：**猜最后一个字符是否相等**。如果相等可以加入 LCS，反之 LCS 必须至少舍弃其中一个

定义 DP\[i, j] = LCS(X\[1...i], Y\[1...j]) 的**长度**，如果 X\[i] = Y\[j]，DP\[i, j] = DP\[i-1, j-1] + 1；如果 X\[i] ≠ Y\[j]，DP\[i, j] = max\{DP\[i-1, j], DP\[i, j-1]}。

(边界情况 DP\[0, j] = DP\[i, 0] = 0)

计算顺序是将 DP\[i, j] 想象为 i+1 行 j+1 列的二维数组，从上到下从左到右进行：

- 每个状态只依赖已经计算好的前缀 (依赖左边、上方、左上方)，所以可以逐行、从左到右填二维表。

时间复杂度：对于两个长度分别为 n,m 的字符串为 𝛩(nm)，相近长度简化为 𝛩(n<sup>2</sup>)

从 DP (LCS 长度) 恢复 LCS：从右下角 `DP[n,m]` 开始：

- 如果字符相等，记录该字符，向左上角移动；
- 如果字符不等，向上或向左移动到 DP 值较大的格子；
- 最后反转记录的字符顺序。

例如 X = BDCABA，Y = ABCBDAB：LCS\[X, Y] = BCBA

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-17%2022.00.45.png)

如果插入和删除成本均为 1，替换成本为无穷大，那么改写字符串的最小成本 **Min Edit Cost** = |X|+|Y|- 2LCS(X,Y)。原因是保留公共子序列，删除 X 中剩余字符，再插入 Y 中缺少的字符。

## Activity Scheduling

给定 n 个活动，每个活动有：开始时间 s<sub>i</sub>、结束时间 f<sub>i</sub>，同一时刻只能进行一个活动。目标是选出最多数量的互不重叠活动。

1. 如果类比矩阵乘法 (选择中间的 k，再分成左右两个子问题)，安排在活动 i 结束之后、活动 j 开始之前的活动 k：最多能安排的数量 DP\[i, j] = max\{DP\[i, k] + 1 + DP\[k, j]}。O(n<sup>2</sup>) 个状态，每个最多枚举 O(n) 个 k，O(n<sup>3</sup>)。

2. 假设活动按开始时间排列。定义 p(i)：活动 i 之后第一个能够兼容安排的活动索引。则 DP\[i] = max\{1 + DP\[p(i)], DP\[i+1]}

   这是典型的 **Include / Exclude DP**：选择 p(i) 就从 p(i) 继续，反之就从下一项继续。DP 部分为 𝛩(n)。

3. no DP **Greedy**：优先选择**结束时间最早的活动**。交换论证：某最优方案第一个元素是 a<sub>k</sub> 将其换成结束时间更早的 a<sub>1</sub> 依然可以衔接原本后面所有活动，且使第一二个活动间隔变大，留下更多塞入活动的机会。之后对剩余活动重复这个论证，就得到 Greedy 算法。

   已按结束时间排序时，选择过程为 O(n)；若需要先排序，总时间为 O(nlog n)。

## Traveling Salesman Problem

TSP 给定 n 个城市和城市间距离 d<sub>ij</sub>，要求：从城市 1 出发，每个其他城市恰好访问一次，最后返回城市 1，使得总距离最短。即寻找最短的 Hamiltonian Cycle。

固定起点后，暴力枚举访问顺序有 (n-1)! 种可能，即阶乘时间复杂度。

先计算从城市 1 出发访问指定集合 S、最后停在城市 j 的最短路径 (Hamiltonian Path)，再加上从 j 返回 1 的成本 (形成 Cycle)。定义 **DP\[1→j, S]** 表示：从城市 1 出发，恰好访问集合 S 中所有城市一次，并最终停在城市 j≠1 的最小成本。

**DP** TSP: **猜最后一个城市 j 从哪个前项 i 来**。先求到 i 的最短路径，再通过最后一条边 i→j 到达 j，**DP\[1→j, S] = min(DP\[1→j, S \\ \{j}] + d<sub>ij</sub>)**，基础状态 DP\[1→1, 1] = 0

当 S 已经包含所有城市 |V|= n 时，我们计算从 1 出发、访问所有城市、停在 j 的最小成本，最后只需要返回城市 1：**TSP = min(DP\[1→j, V] + d<sub>j1</sub>)**

时间复杂度：集合 S 有最多 2<sup>n</sup> 种可能，对于每个集合 S，最后一个城市 j 有最多 n 种选择，所以状态数 O(n2<sup>n</sup>)，每个状态需要枚举倒数第二个城市 i，最多 n 个：**O(n<sup>2</sup>2<sup>n</sup>)**；空间复杂度 O(n2<sup>n</sup>)。

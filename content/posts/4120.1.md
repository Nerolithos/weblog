# CSC4120 L01



# I. Asymptotic Complexity



## 增长率

我们先定义函数 T(n) 表示算法处理一个大小为 n 的输入时，**最差**需要多少“基本操作”。

算法分析的目标不是问：“我的 MacBook 跑这个程序用了多少毫秒？”，而是问：**当输入规模 n 增大时，所需要的工作量怎样增长？**

这就是 **algorithmic complexity**（渐进复杂度） 的基本思想——我们不关心算法的某一精确运行时间

比如在比较保守的 **worst-case complexity（最坏情况复杂度）**下，遍历算法的 wcc 就是 $T(n)\propto n$。



$n \rightarrow \infty$ 时，只保留 T(n) 的 **增长率（rate of growth）**，忽略：multiplicative constants（常数倍）、lower-order terms（低阶项），比如 $T(n)=3n^2+100n+5000 = \Theta(n^2)$。这就是所谓的 **dominant term（主导项）**。

故计算机型号、 CPU、compiler optimization 等具体因素就不再重要——它们作为常系数，在渐进复杂度角度下会被主导项压过——**我们只关心增长率数量级**。



</br>

## 复杂度符号 

| **符号**     | **意思**             | **直观理解**                |
| ------------ | -------------------- | --------------------------- |
| O(g(n))      | Upper bound（Ceil）  | f(n) 最快不超过 g(n) 增长率 |
| \Omega(g(n)) | Lower bound（Floor） | f(n) 最慢不低于 g(n) 增长率 |
| \Theta(g(n)) | Tight bound          | f(n) 增长数量级等于 g(n)    |

将目标函数设作 f(n)，那么三个符号分别严格定义为：

1. **从某个足够大的 n 开始，f(n) 永远不会比 g(n) 快超过一个常数 c 倍**。例如 $n=O(2^n)$ 成立，一个 O(n) 的算法当然也是 O(n^2)。

2. **从某个足够大的 n 开始，f(n) 永远不会比 g(n) 慢超过一个常数 c 倍**。例如 $n^2=\Omega(n)$ 成立。

3. **从某个足够大的 n 开始，c<sub>1</sub>g(n) ≤ f(n) ≤ c<sub>2</sub>g(n)**。我们可将 $\Theta(g(n))$ 理解为一系列与 g(n) 同渐进复杂度 (增长率同数量级) 的函数

如果一个函数在 $\Theta(n^{1.5})$ 和 $\Theta(n^2)$ 之间不断震荡，它不一定能够写成某一个简单的复杂度。故复杂度不只是简单的“删系数留主导”，标准定义很重要。



- 对于：a,b>1   k,r>0 有：$\lim_{n\to\infty}\frac{n^r}{a^n}=0$

  意思是：**任何多项式最终都比指数函数增长得慢。**

  即：n<sup>100</sup>=O(1.01<sup>n</sup>)，即使 1.01^n 看起来增长非常慢。

- 类似的：$\lim_{n\to\infty} \frac{(\log_b n)^k}{n^r} =0$

  即：**任何固定次幂的 logarithm 都比任何正次数的 polynomial 慢。**

> $\boxed{ (\log n)^k \ll n^r \ll a^n }$



</br>

## 好算法远比好硬件重要

$$1 <  \log_c n  <  n  <  n\log_c n  <  n^2  <  n^3  <  \cdots  <  2^n$$

- $\Theta(\log n)$：**GREAT**
- $\Theta(n)$：**GOOD**
- $\Theta(n^2),\Theta(n^3)$：开始昂贵
- $\Theta(2^n)$：**BAD**

一台普通机器 A 和一台大约 **快** 10<sup>7</sup> **倍** 的机器 B。即使硬件性能提升一千万倍，指数算法 2<sup>n</sup> 在输入稍大时仍然荒谬地慢，因为每增加一个输入就计算量翻倍——**好的算法通常比好的硬件重要得多**。



</br>

## 证明复杂度

证明 $T(n)=\Theta(f(n)) $，即证明 $\forall n: T(n)=O(f(n)) AND \exists n T(n)=\Omega(f(n))$ ——**无论输入是什么，都不会比** f(n) **更糟**，且**存在一个 worst-case input，让算法至少做这么多工作。**

因为课程定义：T(n)=  max running time，即 **worst case**，所以上界要证明全部，下界只要证明存在一个 worst case。



**算法复杂度**和**问题复杂度**不同；前者只兜底算法的最差表现，而后者需要证明“存在这么快的算法”以及“任何算法都不可能更快”。比如说 MergeSort=O(nlog n) 是在讨论**某个算法的复杂度。**但是说：sorting requires $\Theta(n\log n)$ 则是在讨论**这个问题本身有多难。**



</br>

# II. D&C, Master Thm.



## Divide and Conquer

分治 (D&C) 表示把一个规模 n 的问题拆成若干更小的同类问题递归解决，再合并：T(n) = divide_time(n) + $\sum_iT(n_i)$ + combine_time(n)。

### InsertionSort

比如 InsersionSort(n)：依次加入原始项并在新数列中将其前移直到前项小于此项。证明：

任意 n 有 𝑇(𝑛)=𝑂(𝑛<sup>2</sup>)：相当于把排序分成了 n 次最差要移动 n 次的子任务

存在 n 使 𝑇(𝑛)=Ω(𝑛<sup>2</sup>)：最坏就是倒序：[n,n-1, ... ,2,1]，第 i 个元素大概要移动 i 次，总次数：

1+2+3+ ... +(n-1) = **order of n<sup>2</sup>**



</br>

## MergeSort 与树递归

D&C 的另一个典型运用是“二分法”，如 MergeSort(n)：$$T(n) = 2T({n \over 2})+\Theta(n) = \Theta(n\log n)}$$

其中 $\Theta(n)$ 来源于 divide & combine 的线性时间，并被主导项掩盖。Merge Sort 每一层总工作量都是 cn，树高约为 log n，因为我们计算的是普通串行算法，不存在并行运算，因此复杂度为 nlogn 级。

### 几何级数

回忆几何级数 (Geometric Sum)：S=1+x+x<sup>2</sup>+ ... +x<sup>h</sup>。当 x ≠ 1，$S= \frac{x^{h+1}-1}{x-1}.$

- 当 x < 1，总和趋向一个常数∈ $[1,  \frac{1}{1-x}]$，S = Θ(1)（第一项主导：Θ of the first term）

- 当 x > 1，总和趋向最后一项，S = Θ(x<sup>h</sup>)（最后项主导：Θ of the last term）

- 当 x = 1，总和为 h，S = Θ(h)

> 几何级数告诉我们在一个递归式中哪项主导结果，类似的，一个二叉树中叶和非叶节点成本谁主导总成本。

### 递归树 (recursion tree)

如果每次分为 b 份，n → b 个 n/b → b<sup>k</sup> 个 n/b<sup>k</sup>，直到  n/b<sup>k</sup>=1 时 不可再分，即 递归深度k = log<sub>b</sub>n

对于一个 a-叉树，对于深度 k 处，节点个数为 **a<sup>k</sup> = n<sup>log<sub>b</sub>a</sup>**（利用恒等式 $x^{\log_a y} = y^{\log_a x}$）

### 用 D&C 证明 MergeSort 复杂度

T(n) = 2T(n/2) +cn

- 非叶节点：根节点 (二分 n 个对象) 的成本为 cn，第 k 层的二分任务成本为 2<sup>k-1</sup>·cn/2<sup>k-1</sup> = cn。每层 cost 相等，**相当于几何级数 x=1 情况**。共 log<sub>2</sub>n 层，故二分总成本为 cnlog<sub>2</sub>n = **Θ(nlogn)**；
- 叶节点：不可二分的最深层每个叶节点的成本为 base-case T(1)=Θ(1)，有 n<sup>log<sub>2</sub>2</sup> = n 个叶，则叶成本为 **Θ(n)**

> 显然的，这里非叶节点即二分过程主导了结果的复杂度：**Θ(nlogn)+Θ(n)=Θ(nlogn)**

![](https://i.postimg.cc/151fzS7G/jie-ping2026-09-07-16-03-48.png)

### 用数学归纳法(Induction)证明

猜 T(n) = O(nlogn)，即证明存在 c<sub>1</sub> 使 T(n) ≤ c<sub>1</sub>nlogn。

假设对 x<n，T(x) ≤ c<sub>1</sub>xlogx 成立，代入 T(n) = 2T(n/2)+cn，于是 T(n)  ≤ 2c<sub>1</sub>(n/2)log(n/2)+cn = c<sub>1</sub>nlogn - c<sub>1</sub>n + cn。

那么只要 c<sub>1</sub> ≥ c，就满足 T(n) ≤ c<sub>1</sub>nlogn，QED。

整个过程以猜代证是，故又称 substitution method



</br>

## Master Theorem

MergeSort 是一种每层非叶节点成本均为 cn 的平衡情况，递归不一定如此：

- 比如 T(n) = T(n/4) + T(n/2) + n<sup>2</sup>，根节点成本为 n<sup>2</sup>，下一层为  (n/4)<sup>2</sup> +  (n/2)<sup>2</sup> = 5n/16……以此类推，总成本为 $n^2 \left[ 1+\frac5{16}+ \left(\frac5{16}\right)^2+\cdots \right].$，根据几何级数推论 (5/16 < 1)，总成本为**第一项主导**：n<sup>2</sup>Θ(1) = Θ(n<sup>2</sup>)。

- 反过来，T(n) = 4T(n/2)+n 的节点增长率 (x) 为 2>1，故总成本为**最后项主导**：Θ(x<sup>h</sup>) = Θ(4<sup>log<sub>2</sub>n</sup>) = Θ(n<sup>2</sup>)。

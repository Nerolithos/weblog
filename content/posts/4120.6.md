# CSC4120 W08  最短路径问题

# I. Bellman-Ford Algorithm

## Shortest Path Problem

给定一个带权有向图：G = (V, E)，w(u, v) 权重可以为一切**整数**

δ(s, c) 表示从 s 到 c 最短权重和 Shortest Distance，δ 的数值唯一但对应最短路径不一定唯一。如不可达，记作 δ = ∞

Single-Source Shortest Path (**SSSP**)：起点固定时简写为 δ(v)，π(v) 表示最短路径上 v 的前驱节点。前驱指针可以帮助我们重建完整路径：从终点不断沿着 π 向前直到起点。

---

</br>

</br>

## Optimal Substructure & Bellman Equation

> Sub-paths of shortest paths are also shortest paths 最短路径的子路径也必须最短

s ⇝ u ⇝ t：若有更短 (s, u) 可以替换当前路径，那 (s, t) 就不是最短

对于任意三个节点有三角不等式 δ(s, t) ≤ δ(s, u) + δ(u, t)，如果 u 位于某条最短路径上，等号成立

**Bellman Equation**：从 s 到 t 的最短路径，最后一步必然来自某个前驱节点 π\[v] = u —— **δ(t) = min \{δ(u) + w(u, t)}** 到达 t 的最短距离，等于所有可能的最后一步中，总距离最小的那个

问题是我们并不一定知道 δ(u) —— 先猜一个保守的值，然后不断改进。

</br>

### 负权边和负权环

负权边并不一定有问题，问题在于 Negative Cycle 负权环会**破坏最短路径存在性**：越绕权重和无限减小。因此对能够从 `s` 到达、并且可以从该负环继续到达的终点，最短路径权重没有有限最小值，通常记为 -∞。

没有负权环时只需考虑 Simple Path (不重复节点的路径)：如果一条路径重复了节点，那么中间一定存在一个 Cycle，当没有负权环时，这个 Cycle 的权重非负。删去这个 Cycle，不会增加路径总权重。所以我们总能找到一条简单最短路径。

> 包含 V 个节点的 Simple Path 最多有 V-1条边—— **Bellman-Ford 只需要 V-1 轮**

</br>

### Relaxation 松弛操作

我们不知道真正的 δ(v)，所以先**维护一个估计值 d\[v] (或记作 $\hat{\delta}(v)$)**。初始化 d\[s] = 0，d\[v] = ∞ (v ≠ s)；检查一条边 (u, v) 后，**如果 d\[u] + w(u, v) < d\[v] 说明经过 `u` 可以更便宜地到达 `v`**，于是更新 d\[v] = min\{d\[v], d\[u] + w(u, v)} 更新成功则记录 π\[v] = u。

- 估计值 d 只能减小，不会增加；

- 在不存在相关负权环时，估计值不会小于真正的最短距离：d\[v] ≥ δ(v)；

  因为每一个有限估计值，都来自一条实际可行的路径。既然 δ(v) 已经是所有路径中最小的，它不可能比真正最短距离还小。称这种估计为 **Safe Estimate** 安全估计。

---

</br>

</br>

## Bellman-Ford Algorithm

不断对所有边进行 Relaxation，直到不能再更新，**最多 V-1 轮**

每一轮至少可以让最短路径上下一层的节点获得正确的最短距离。

所以 Round 1 保证所有最短路径只含 1 条边的节点正确…… Round k 保证所有最短路径最多含 k 条边的节点正确。

⚠️ 每一轮可能让多个层次的节点同时得到正确答案。检查顺序恰好沿最短路径方向 s⇝v，一轮就能把整条路径更新完。最差情况 (V-1)就是完全逆序。

```pseudocode
def bellman_ford(G, s):
    for v in G.V:
        d[v] = float("inf")
        parent[v] = None
    d[s] = 0
    for _ in range(len(G.V) - 1):
        for u, v, w in G.E:
            if d[u] != float("inf") and d[u] + w < d[v]:
                d[v] = d[u] + w
                parent[v] = u
    # One additional pass: detect reachable negative cycles
    for u, v, w in G.E:
        if d[u] != float("inf") and d[u] + w < d[v]:
            return "Reachable negative cycle"
    return d, parent
```

如果不存在可达负权环，那么经过 V-1 轮后，所有最短距离已经正确，无法再成功松弛。如果第 V 轮还能找到松弛，说明存在可达负权环。

</br>

### Time Complexity & Example

初始化 O(V)，遍历所有边 O(E) 共进行 V-1 轮，最后检查负权环再遍历一次 O(E)：O(V + VE + E) = **O(VE)**

Sparse (E = Θ(V))：Θ(V<sup>2</sup>)；Dense (E = Θ(V<sup>2</sup>))：Θ(V<sup>3</sup>)

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-02%2012.56.53.png)

Round 1：从源点 0 的直接出边得到 d\[1] = 6，d\[2] = 5，d\[3] = 5

Round 2： 4, 5 可达，然后通过负权边 d\[2] + w(2, 1) < d\[1] 和 d\[3] + w(3, 2) < d\[2] 更新 d\[1] = 3, d\[2] = 3，且 π\[1] = 2，π\[2] = 3

Round 3：上一轮 d\[1]、d\[2] 更新，故本轮 d\[4] 可以更新，同时 6 可达

……

> ⚠️ 每轮只能探索已发现节点出发的边 (第一轮时只有 s)；
>
> ⚠️ 对于 (u, v) 每次用 Relaxation 更新 d\[v] 时使用的是上一轮的 d[u] 值，即使本轮 d\[u] 有更新。

# II. Dijkstra DAGs

## DAG Shortest Path

对于 DAG，Bell-Ford 是存在冗余的 (正确处理顺序未知所以反复扫描所有边)，不同于 Bell-Ford 不允许负权环，DAG 不存在环，所以允许负权边。DAG 最短路径问题可以只 Relax 每条边一次：先进行 Topological Sort，然后按拓扑顺序处理节点。

当我们按照拓扑顺序处理节点 `v` 时，所有可能指向 `v` 的前驱节点都已经被处理过。因此，每个前驱节点的最短距离都已经正确，并且所有进入 `v` 的边都已经完成松弛。时间复杂度：拓扑排序 (DFS) **Θ(V+E)** + 每个节点处理一次、每条边 Relax 一次 **Θ(V+E)**，T(V, E) = **Θ(V+E)**。

</br>

## Dijkstra's Algorithm

DAG 可以依靠 Topological Order，但普通图可能有环，无法拓扑排序。

Dijkstra 提出**每次选择当前距离估计值最小的、尚未确定最短距离的节点**，一种 **Greedy Algorithm** 贪心算法。

把节点分为两个集合：S (Closed Set) 表示最短距离已**确定且固定** (δ(v) = d\[v]) 的节点集合；Q (Open Set) 表示只有当前距离估计值，之后可能继续下降的节点集合。初始化 S = ∅，d\[s] = 0，d\[v] = ∞。 (一旦节点进入 S，它的距离就永远不会再改变，**只在 Dijkstra 非负边权条件下保证**)

每次执行以下步骤：

1. 从 Q 中**选择 `d` 最小的节点** `u`，将其加入 S ("**Extract-min**")。

   ⚠️ Dijkstra 作为 **Weighted BFS-Extention** (BFS 的一种推广) 算法，每轮中仅有 δ 最小的点不可能再被缩短所以可以加入 S，其余边若在下一轮发现被其他同层 δ 更小的节点指向都有可能缩短。

2. 对 `u` 的所有出边 (从 u 指向的节点) 执行 Relaxation。

3. 重复直到 Q 为空。

Dijkstra 与 Bellman-Ford 的核心区别：**Dijkstra 能判断什么时候一个节点的估计值已经最终正确** (加入 S 时)

```python
DIJKSTRA(G, w, s)
    INITIALIZE-SINGLE-SOURCE(G, s)
    S = ∅
    Q = G.V
    while Q ≠ ∅
        u = EXTRACT-MIN(Q)
        S = S ∪ {u}
        for each v in Adj[u]
            RELAX(u, v, w)
RELAX(u, v, w)
    if d[v] > d[u] + w(u, v)
        d[v] = d[u] + w(u, v)
        π[v] = u
```

这里 `Q` 是 **Min-Priority Queue (最小堆)**，从尚未确定的节点中选出距离估计值最小的节点 (Extract-min)，Key 为 `d[v]`。

当 Relaxation 使 `d[v]` 减小时，需要对优先队列执行 Decrease-Key (更新节点变小的距离)

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-04%2014.24.33.png)

Dijkstra 的核心 Invariant (循环不变式)：v ∈ S → d\[v] = δ(v) 即每当一个节点加入 S，它的距离估计值已经等于真正的最短距离。

Proof by contradiction 每次 Extract-Min 都能维持这个性质：假设我们选择了 Q 中距离最小的节点 d\[t] = a，但是它真正的最短距离其实更小 δ\[t] = b ——即存在一条尚未发现的更短路径。这条真正最短路径从源点 `s` 出发，沿着它找到第一个不在 S 中的节点 `y`，其前驱节点 `x` 一定已经在 S 中。而 `x` 的所有出边都已经被 Relax，所以 d\[y] ≤ d\[x] + w(x, y)，由于 `x→y` 位于真正的最短路径上，d\[x] + w(x, y) = δ(y)，由于 d\[y] ≥ δ(y) (估计值不会小于真实距离)，所以 d\[y] = δ(y)，由于**所有边权非负**，从 y 走到 t: d\[t] = δ(y) ≤ δ(t) = b，但是 `t` 是 Q 中估计值最小的节点，所以 d\[t] ≤ d\[y] ≤ b，和 d\[t] = a 矛盾。

这就是为什么 Negative Weights 导致 Dijkstra 失败：已经加入 S 的节点 `u`，**若有一个负权边指向它，其距离竟还可以下降**，破坏了 Invariant，所以 Dijkstra 需要**所有边 w(u, v) ≥ 0**

| 性质           | DAG Shortest Paths | Dijkstra                  | Bellman-Ford      |
| -------------- | ------------------ | ------------------------- | ----------------- |
| 允许有向环     | 否                 | 是                        | 是                |
| 允许负权边     | 是                 | 否                        | 是                |
| 允许可达负权环 | DAG 不可能有环     | 不适用                    | 可检测            |
| 处理顺序       | Topological Order  | Minimum Estimated d       | 反复扫描所有边    |
| Relaxation     | 每条边一次         | 每条边一次（标准实现）    | 每条边最多 V-1 轮 |
| 复杂度         | Θ(V+E)             | O((V+E)log V) Binary Heap | O(VE)             |

# III. Bidirectional Dijkstra & A<sup>\*</sup>

Dijkstra 的特点是每次选择离源点 `s` 最近的节点 u = min<sub>v∈Q</sub>d\[v]，因此它的搜索范围会从 `s` 向所有方向扩散 (类-BFS)。寻找从 `s` 到 `t` 的最短路径时，虽然在 `t` 进入 Extract-Min 时提前停止，但仍可能探索大量无关 (属于其他分支) 的节点。

假设每个节点平均有 b 个分支 (边权为 1)，`s` 到 `t` 的最短路径有 d 条边：

- 每层需要探索 1，b，b<sup>2</sup> ... b<sup>d</sup>；
- 求和后为 n = **Θ(b<sup>d</sup>)** 数量级 (理想最差情况)

</br>

</br>

## Bidirectional Search

如果从两端 (s, t) 同时搜索，让2个搜索区域在中间相遇，由此得到 **n<sub>BD</sub> = Θ(2b<sup>d/2</sup>) = 2√n**

引入两个集合：

- S<sub>s</sub>：从源点 s 正向搜索时已经确定的节点
- S<sub>t</sub>：从目标 t 反向搜索时已经确定的节点

对于每个节点 `v`，保存两个距离：

- v.s：当前从 s 到 v 的距离估计
- v.t：当前从 t 到 v 的距离估计

**⚠️ 反向搜索不是把原图当作无向图** —— 从 `t` 反向搜索时，应使用反向边，也就是在 Reverse Graph 上运行 Dijkstra。

> 当某个 u ∈ S<sub>s</sub> ∩ S<sub>t</sub> 即从 s 和 t 出发的搜索都确定距离后，终止
>
> **但第一次相遇的节点不一定就在最短路径上**，不能仅仅在两个搜索区域第一次碰到时，就立即把那个交点对应的路径当作最短路径。

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-06%2014.28.34.png)

</br>

## A<sup>\*</sup>

Dijkstra 算法的本质是没有方向性的 (在平面上是涟漪状遍历)，更优算法需要知道前进方向而非向空间所有方向试错。

Dijkstra 的优先级是当前已知从 s 到 v 的最短路径成本 δ(v)，换句话说 **Dijkstra 只关心已经走了多远**。但如果我们的目标是 `t`，还应该关心**从当前节点 `v` 到 `t`，预计还要走多远**？—— **f(v) = g(v) + h(v)**

- g 表示 **Past Cost**：从 `s` 到 `v` 的当前已知成本；

- h 表示 **Future Cost Estimate**：从 `v` 到 `t` 的估计成本，属于 **Heuristic Function 启发式函数**，也叫 Potential Function (势函数)；

  和为 **Estimated Total Cost**：经过 `v` 到达 `t` 的估计总成本。

A star 依然使用两个集合：S (已处理 **NOT necessarily closed**)、Q (待处理 Open)，初始 v ≠ s，g\[s] = 0，g\[v] = ∞

1. 从 Q 中选择 g(v) + h(v) 最小的节点 u

2. Relaxation：g(v) = min\{g(v), g(u) + w(u, v)}，若 g 下降，f 也下降

3. 如果 `v` 已经在 S 中，但其**距离又被改善，就把它重新放回 Q**

   这一步是 A<sup>\*</sup> 与普通 Dijkstra 的重要区别：**Heuristic 不一定估计准确，A\* 不能保证每个节点第一次进入 S 时，其最短距离就已正确**

</br>

### Heuristics

**Admissible Heuristics 可采纳启发式**：不能高估从当前节点到目标的真实最短距离 h(v) ≤ δ(v, t)，满足时称为 **Admissible**。

- 若高估，某条真正最短路径上的节点，算法就可能认为这条路径很差，提前选择其他路线。**Admissibility 保证 A\* 在目标节点 `t` 被取出时，找到的就是最短路径**

**Consistent Heuristics 一致性启发式**：从 `u` 到终点的估计成本，不能大于**先走到 `v` 的真实成本 + 从 `v` 到终点的估计成本**h(u) ≤ w(u, v) + h(v)

- 假设 h(t) = 0 且节点能够到达目标，一致性启发式一定 Admissible (反之不成立)，且 S 节点无需重新打开，即节点首次进入 S 时距离一定最优
- 要求**任意两个相邻节点之间的估计值变化不超过实际边权**，所以它的约束更严格

</br>

### A<sup>\*</sup> ≡ Dijkstra

**Reweighting (重赋值权重)**：w'(u, v) = w(u, v) + h(u) - h(v)

- 重赋值权重后，所有路径的**相对长度保持不变**

- A<sup>\*</sup> 等价于用重复值 w' 后的图跑 Dijkstra

  **min g'(v) = min f(v)**

- > ⚠️ Consistent Heuristic 的作用，就是保证重新赋权后的所有边权非负，从而让 A\* 具备 Dijkstra 的正确性性质：w'(u, v) = w(u, v) + h(u) - h(v) **≥ 0**

</br>

### Designing h(v)

**Euclidean Distance**：即将 u, t 两点之间的直线距离作为 h(u)

- 实际道路可能弯曲，但道路长度不小于直线距离 h(u) ≤ δ(u, t)：**Admmisible**

- 三角不等式 d(u, t) ≤ d(u, v) + d(v, t)，w(u, v) ≥  d(u, v)，于是 h(u) = d(u, t) ≤ **w(u, v) + h(v)**

  因此也 **Consistent**

**Manhattan Distance**：对于水平竖直网络，**h(u) = |x<sub>t</sub> - x<sub>u</sub>| + |y<sub>t</sub> - y<sub>u</sub>|**

- 在**每次水平或竖直移动成本为 1 的网格中**，Manhattan Distance 是 **Consistent**

- 如果允许成本为 1 的对角移动，直接使用 Manhattan Distance 可能**高估真实距离**

</br>

### Landmark Heuristics

Euclidean Distance 适用于地图，但很多抽象图没有几何坐标，就无法直接计算节点间的直线距离 —— 选取一个或多个 **Landmark** (地标节点)，预先计算它们与其他节点之间的最短距离。然后利用这些距离估计任意节点 `u` 到目标 `t` 的距离。

假设一个地标 A，根据三角不等式 δ(u, t) + δ(t, A) ≥ δ(u, A) 且 δ(A, u) + δ(u, t) ≥ δ(A, t) 移项后得到 ⚠️ **δ(u, t) ≥ max\{δ(u, A) - δ(t, A), δ(A, t) - δ(A, u)} = h(u)**

- 因为 h(u) ≤ δ(u, t)，**Admissible**

- 公式有两个方向，因为有向图 必须分别考虑 从节点到 Landmark & 从 Landmark 到节点
- 如果图是无向图，可以简化成 h(u) = |δ(A, t) - δ(A, u)|

假设选择多个地标 A, B, C：h(u) = max\{h<sub>A</sub>(u), h<sub>B</sub>(u), h<sub>C</sub>(u)}

> **多个 Landmark 可以让 Heuristic 更精确，从而减少 A\* 探索的不必要节点**
>
> 理想 Landmark 可以使上述下界恰好等于真实距离

# CSC4120 W09  贪心算法

Greedy (贪心) 指每一步都选择**当前看来最有利**的选项，并且通常不撤销之前的选择。必须同时满足：

- 选择有利的局部方案；
- 保证局部选择不会破坏最终的全局最优解 (需证明)

</br>

</br>

## Spanning Tree 生成树

对于一个 **Connected Undirected** Graph G = (V, E)，Spanning Tree 是满足以下性质的子图：

1. 包含全部顶点 V
2. Connected 连通
3. Acyclic 无环

⚠️ 树的性质：|E<sub>Tree</sub>| = |V| - 1 (m = n - 1)

- 树中任意两点之间存在唯一一条简单路径；
- 假如任意新边必产生环，且从这个环删除任意一边，结果仍是一棵树。

Minimum Spanning Tree (MST) 是在这些树中寻找**总边权最小**的一棵：**arg min<sub>Tree</sub> Σ w(e)**

</br>

### MST Cut Property

一个 Cut 将顶点划分为两个不相交集合 S 和 V-S，Crossing Edge 指一端在 S、另一端在 V-S 的边

>⚠️ 对任意 Cut 方案，权重最轻的 crossing edge 都属于至少一棵 **MST**。

- 如果有多条相同权重的最轻边，它们未必同时出现在所有 MST 中；
- 不是说一条边只要很轻，就可以无条件加入当前解——

</br>

### Safety Lemma (of spawning MST)

设 X 是已选出的边集合。如果存在一棵 MST 包含 X，则称 **X is safe**。也就是说当前已选出的边，仍有可能扩展成一棵 MST。

如果一个 **Cut respects X**，意味着 X 中没有任何边跨越这个 Cut。

> X safe, C respects X, e lightest across C → **X ∪ \{e} safe**
>
> 只要当前选择没有错，那么沿着一个不切断已选边的 Cut，加入最轻跨越边，就仍然不会错。

#### Proof by Exchange Argument

假设 X ∈ some MST T<sub>0</sub>；e 是一个 respects X 的 Cut 上的最轻边。

如果 e ∈ T<sub>0</sub>，直接成立。

否则：

1. 向 T<sub>0</sub> 加入 e，**形成一个 Cycle**
2. 因为 e 跨越 Cut，这个 Cycle 必须还有另一条跨越 Cut 的边 e<sub>0</sub> (否则 T<sub>0</sub> 不连通)
3. 因为 e 是最轻的 Crossing Edge，可以删除 e<sub>0</sub>：**T' = T<sub>0</sub> - \{e<sub>0</sub>} + \{e}**。新树权重 ≤ T<sub>0</sub>，**T' 仍是 MST**

因为 Cut respects X，有 e<sub>0</sub> ∉ X，因此删除 e<sub>0</sub> 不会破坏已经选出的 X，即 **X ∪ \{e} ⊆ MST T'**

## Kruskal Algorithm

> 按照边权从小到大排序，每次加入不会形成环的最轻边。

假设已经选择的边集合为 X，下一条被选中的边为 e = (u, v)

由于 Kruskal 不允许形成 Cycle，因此 `u` 和 `v` **一定位于不同的 Connected Components**。考虑把 `u` 所在的整个 Component 与其余节点分开的 Cut，这个 Cut：

- 不会切断任何已选边，因此 respects X。
- e 是这个 Cut 上的最轻边，否则更轻的跨越边早已被考虑且可以加入。

根据 Safety Lemma，X ∪ \{e} is safe；所以每次选择都保持正确，当算法选择了 n-1 条边时，得到一棵 MST。

### Union Find

我们提到“`u` 和 `v` **一定位于不同的 Connected Components**”，所以必须判断

Union-Find (Disjoint Set Union, DSU) 支持三个操作：

- `makeset(x)`  创建仅包含 x 的集合

- `find(x)`  找到 x 所在集合的代表 Root

- `union(x,y)`  合并两个集合

```pseudocode
for each vertex v:
    makeset(v)
X = ∅
sort edges by increasing weight
for each edge (u, v):
    if find(u) != find(v):
        X.add((u, v))
        union(u, v)
return X
```

Union-Find 用树表示集合，Root 代表集合的身份。如果每次随意合并 (比如直接衔接)，那么 `find` 可能需要沿着很长的路径走到 Root。

为避免树太深，采用 Union by Rank：**将 Rank 较低的树连接到 Rank 较高的树的根上**：

⚠️ **Rank (秩) 是树高的紧上界，初始化为 0，在没有 compression 情况下等于树高**

如果两个 Root 的 Rank 相同：

- 任选一个作为新 Root，另外一棵接在新根下
- 新 Root 的 Rank 增加 1

如果 Rank 不同：

- 较低 Rank 的 Root 指向较高 Rank 的 Root (小树挂到大树根下)
- Rank 不变

> ⚠️ 因为 Rank 0 至少 1 个节点；Rank 1 由两个 Rank 0 树合并，至少 2 个节点；Rank 2 由两个 Rank 1 树合并，至少 4 个节点；Rank 3 至少 8 个节点…… **Root Rank = k，|V| = n ≥ 2<sup>k</sup>**，反之 **k ≤ log<sub>2</sub>n，树高也是 O(logn)**
>
> 无 compression 情况下，find()、union() 也是 O(logn)

</br>

### Path Compression

Rank 并不总等于当前实际深度，在 Path Compression (路径压缩) 后深度可能下降，但 Rank 不会。

路径压缩：在执行 find() 时，让沿途经过的节点直接指向 Root；即第一次 find() 仍需沿路径找到 Root，但后续的查找会快很多。

时间复杂度为 Amortized (摊还的) **O(log<sup>\*</sup> n)** per op.，其中 log<sup>\*</sup> n 是 **Iterated Logarithm**，即需要连续取多少次 2 的对数才能降到不大于 1：log<sup>\*</sup>(1000) = 4

⚠️ Krustal 总复杂度：O(mlog m) 排序所有边，O(mlog<sup>(\*)</sup> n) Union find，因为简单连通图 n-1 ≤ m ≤ O(n<sup>2</sup>), log m = Θ(log n)。综上，**T<sub>Krustal</sub> = O(m log n) = O(|E|log|V|)**

## Prim Algorithm

类似于 Krustal，Prim 也在找 MST，但构造过程不同：

Kruskal：从最轻边开始，可以同时维护多棵小树，不断合并 Connected Components。

Prim：从任意一个起点开始，始终维护一棵 Connected Tree，每次选取从当前树通往外部的最轻边。

**Prim 与 Dijkstra 都使用 Priority Queue**，但维护的 `d[v]` 含义完全不同。

|          | Prim                             | Dijkstra                     |
| -------- | -------------------------------- | ---------------------------- |
| 目标     | MST                              | Shortest Paths               |
| `d[v]`   | 从当前集合 S 到 v 的最小单条边权 | 从源点 s 到 v 的最短路径长度 |
| 更新方式 | min(d[v],w(u,v))                 | min(d[v],d[u]+w(u,v))        |
| 贪心选择 | 最轻的 Crossing Edge             | 最短的当前路径               |

⚠️ Prim 不累加路径长度；Dijkstra 累加路径长度

## Huffman Encoding

“一个月球车有 1/2 概率向前，1/4 概率向后，1/8 概率向左，1/8 概率向右，如何编码最节省通信成本？”

如果使用普通的定长编码 (Fixed-length Encoding)，4 种指令需要 log<sub>2</sub>4 = **2 bits/operation** (即 00, 01, 10, 11)

从哈夫曼编码视角，向前概率高达一半，理应让它用更短的编码：**高频字符使用更短 Codeword；低频字符使用更长 Codeword**——

> 向前 0，向后 10，向左 110，向右 111——平局指令长度 L = Σf<sub>i</sub>d<sub>i</sub> = 50%x1 + 25%x2 + 25%x3 = **1.75 bits/operation**

无歧义 (Ambiguity)？不定长编码缺乏周期性指令分隔，必须让机器自行判断如何”句读“，关键在于使用 **Prefix-free Code (前缀码)**。

也就是说任何一个完整的指令编码，都不能是另一个指令编码的前缀——比如存在 0 和 10，其他指令就不能以 10  或 0 作为开头，所以 3 bit 指令只能选 111, 110。

解码：想象一颗满二叉树 (每个节点有 0/2 个孩子)，从根出发向子节点方向，每次加一位 左0/右1 前缀。由于 **Prefix-free Property**，所有非叶节点是其叶节点的前缀，那么可以用所有叶节点表示一种合法编码。解码时从根出发走到叶就找到了对应指令，返回根并重复。

![∂](https://img.nero-lithos.com/posts/sywhd.png)

### Huffman Greedy

Huffman 的优化目标是最小化平局指令长度 L = Σf<sub>i</sub>d<sub>i</sub> (frequency x codeword length)

Huffman Tree 的节点信息包括权重 (即 codeword frequency)

规则非常简单：**每次选择频率最小的两个节点，创造一个权重为二者之和的新节点，作为它们的父节点**。

最终构造出一棵 Huffman Tree，它的总成本可以直接通过所有合并权重 (非叶权重) 相加求得。因为每次合并的两个子树中的所有字符，深度都会增加 1。因此增加的编码成本恰好是这两个子树的频率之和。

![](https://img.nero-lithos.com/posts/%E6%88%AA%E5%B1%8F2026-11-09%2021.46.49.png)

Greedy Choice Property：

存在一棵最优编码树，使频率最小的两个字符 f<sub>1</sub>, f<sub>2</sub> 是最深层的一对 Sibling Leaves；

直觉：频率越低，放在更深处的代价越小。通过交换叶子位置，可以把最小的两个频率放到最深的兄弟位置而不增加总成本。

Optimal Substructure：

将这两个字符合并成一个新字符：f' = f<sub>1</sub> + f<sub>2</sub>，原问题减少为 n-1 个字符的问题；

如果合并后的最优树为 T'，那么 C(T) = C(T') + f<sub>1</sub> + f<sub>2</sub>。因此只要递归求解更小问题，就能构造原问题的最优解。

使用 **Min-Heap**，每次取两个最小值并插入合并值：**O(nlog n)**。

</br>

### Entropy 信息熵

Entropy 衡量一个概率分布的不确定性：假设字符 i 出现概率为 p<sub>i</sub>，根据香农定理 (**Shannon's Theorem**) 其信息量 I<sub>i</sub> = log<sub>2</sub> p<sub>i</sub><sup>-1</sup> (至少需要这么多 bit 表示)，熵 **H = Σ p<sub>i</sub> log<sub>2</sub> p<sub>i</sub><sup>-1</sup>** (bits per symbol)，这是理想下界。

例如月球车问题的 H = 1.75 bits/symbol。我们发现，当所有概率都是 2<sup>-k</sup> 形式时，Huffman 可以恰好实现相应的编码长度：d<sub>i</sub> = log<sub>2</sub> p<sub>i</sub><sup>-1</sup>，于是平均编码长度恰好等于信息熵。

## Set Cover

给定一个全集 B，以及若干子集 S<sub>1</sub>, S<sub>2</sub>, ... S<sub>m</sub> ⊆ B。目标是选择尽可能少的子集，使它们的 Union (并集) 等于 B。

例如：每所学校可以覆盖附近 30 km 内的城镇。如何选择尽可能少的学校，覆盖所有城镇？



### Set Cover Greedy

规则：每次选择能够覆盖最多尚未覆盖元素的集合

但和 MST、Huffman 不同的是，**Set Cover 的 Greedy Algorithm 不保证找到全局最优解**。

Approximation Ratio：虽然不能保证最优，但我们可以证明 Greedy 的结果不会比最优差太多

设全集中元素数量 n；最优解需要的集合数量 k；执行第 t 轮后仍未覆盖的元素数量 n<sub>t</sub>。

因为最优解 k 个集合覆盖所有元素，所以其中至少一个集合在第 t 轮覆盖了 n<sub>t</sub>/k 个尚未覆盖的元素，否则 k 个集合加起来也无法覆盖全部 n<sub>t</sub> 个元素

而 Greedy 每次选择能覆盖最多新元素的集合，因此它至少也能覆盖 n<sub>t</sub>/k 个元素；所以 **n<sub>t+1</sub> ≤ n<sub>t</sub> - n<sub>t</sub>/k**；递推 **n<sub>t+1</sub> ≤ n(1 - 1/k)<sup>t</sup>** 

利用 1 - x ≤ e<sup>-x</sup>，n<sub>t</sub> ≤ ne<sup>-t/k</sup>，使所有元素被覆盖：ne<sup>-t/k</sup> < 1，即 t > k ln n。Greedy 约 O(k log n) 轮完成覆盖。
